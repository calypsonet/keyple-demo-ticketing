# Changelog
All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]
### Breaking changes
- Components renamed with the English ticketing terms (the applications are installed as new applications: the
  previous ones are to be uninstalled, and their settings are not taken over):
  - "inspection" instead of "control": `src/inspection` directory, `kdt-inspection-app` artifact, application id and
    package `org.calypsonet.keyple.demo.inspection`, application "Keyple Demo — Inspection";
  - "sales" instead of "reloading" for the demo selling and loading the tickets ("reload" designating, on a Calypso
    card, the reloading of its stored value): `src/sales` directory, packages `org.calypsonet.keyple.demo.sales`,
    application ids and iOS bundle id, `kdt-sales-server`, `kdt-sales-android-app`, `kdt-sales-multiplatform-app`,
    and `kdt-sales-pc-dotnet-app` artifacts, applications "Keyple Demo — Sales", "Keyple Demo — Sales (Interop)", and
    "Keyple Demo — Sales (.NET)".
- Remote services of the sales server, named after the business operations:
  - Keyple Distributed: `READ_CARD_AND_LOAD_CONTRACT` (instead of `READ_CARD_AND_WRITE_CONTRACT`) with
    `LoadContractInputDto`/`OutputDto`, and `PersonalizeCardInputDto`/`OutputDto` (instead of `CardIssuance...`);
  - Server JSON API: `SELECT_APP_AND_LOAD_TRIPS` with a `tripsToLoad` field (instead of
    `SELECT_APP_AND_INCREASE_CONTRACT_COUNTER` and `counterIncrement`); JSON fields `tripsToLoad` (instead of
    `ticketToLoad`), `name` (instead of `title`), and `contracts` (instead of `validContracts`, the expired contracts
    being included);
  - same status codes for all the services (`RemoteServiceStatus`, `0` to `8`): a card not personalized is `4` (instead
    of `3`) and an expired environment `5` (instead of `4`) for the services of the .NET client, which distinguish the
    card communication errors (`1`) from the other errors (`2`); a card which is not the one read before is `6`.
- Sales server REST API: `GET /transactions` and the Server-Sent Events stream `/transactions/stream` (instead of the
  long polling endpoint `/activity/events/wait`), `GET /card/sam-availability` returning `isSamAvailable` (instead of
  `/card/sam-status` and `isSamReady`), transaction types `LOAD`, `PERSONALIZATION`, and `FAILURE` (instead of `RELOAD`,
  `ISSUANCE`, and `FAIL`), and JSON key `loadedContract` (instead of `contractLoaded`).
- Common library: immutable model (`data class` structures modified by copy, `contractPriorities` list instead of the
  four `contractPriority1..4` fields), codecs (`RecordCodec`) instead of parsers, `CardConstants` split by theme
  (`CalypsoAids`, `CalypsoFiles`, `DefaultKifs`, `StorageCardBlocks`, `MifareClassicBlocks`, `PkiTestCertificates`),
  `Location` and `LocationRepository` in the `reference` package, `RemoteServiceId` in the `dto` package, and `code`,
  `label`, `fromCode()` for `PriorityCode` and `VersionNumber` (instead of `key`, `value`, `findEnumByKey()`).
- Build requirements: Java 17 for all the Java and Kotlin components (server, common library, Android applications),
  .NET 10 for the .NET client, Node.js 24 for the dashboard.

### Added
- Functional documentation (`docs/functional-documentation`): scope, use cases, business rules, results, and messages
  of the demo for a functional audience, with diagrams (PlantUML, generated at rendering) and a glossary, in the graphic
  charter of the CNA documents. Published as PDF and standalone HTML files (`kdt-functional-documentation-YY.MM.DD`)
  attached to each GitHub release, and generated by the CI of the pull requests for review. As the applications, its
  version is the release tag (YY.MM.DD), its date the date of this tag (`99.99.99` and the build date outside the
  releases), and its reference (`261016-FD-KeypleDemoTicketing`) is fixed.
- Unit tests of the business rules, run by the CI: common library (codecs, data types, event structure), sales server
  (personalization and loading rules), validation and inspection apps (rules and Calypso procedures).
- CI checks: log and exception messages of all the components (`check-messages.py`), layered architecture of the
  Android applications (`check-android-architecture.sh`), files which must stay identical between the Android
  applications (`check-android-twin-files.sh`), and ESLint for the dashboard.
- Validation app: anti-passback check for the storage cards.
- Sales server: `CARD_FULL` (`7`, no empty contract record nor expired or exhausted contract to replace) and
  `EVENT_WRONG_VERSION` (`8`, last event of an unexpected version) statuses.
- Sales clients: the result screens return automatically after 5 seconds (home screen after a success, previous screen
  after an error), the remaining time being shown by a bar and in the "Retry (8)" button.

### Changed
- All the applications: same English ticketing vocabulary in the displayed texts ("ticket", "card", "Season pass",
  "Multi-trip ticket", "Card rejected", "Select the terminal", "Payment confirmed", etc.) and English typography;
  technical messages are no longer displayed (generic text, the cause being logged); the clients display the same
  messages for the statuses of the server.
- Android applications: layered architecture with ports and adapters, the domain being synchronous and transposable to
  another language (current date provided by a `Clock` port); one use case per user operation and a
  `CardReaderSession` instead of a single `TicketingService`; typed results of the procedures, translated into texts by
  the UI; dependency injection with Hilt and KSP instead of Dagger and kapt; coroutines bound to the lifecycle and
  deprecated Android APIs replaced; Java 17 as source and target level.
- Multiplatform client: code organized in `ui` and `data` packages, Android application moved to an `androidApp`
  module (Android Gradle plugin 9), server check and configuration in dedicated classes, R8 shrinking enabled.
- Sales server: card processing split by business operation and dispatched by `RemoteServiceDispatcher`; Quarkus REST
  instead of RESTEasy classic; logging configured by Quarkus.
- Reactivity of the terminals: the operations on the readers and the sounds run on dedicated threads, the stop of the
  card detection (about 440 ms on the Bluebird terminals) no longer delaying the display; the inspection result is
  displayed in an overlay of the card reader screen instead of a new screen; the "Please wait" indicator is removed.
- Inspection app: locations provided by the common library, displayed by their name; the SAM is no longer filtered on
  its power-on data.
- Sales Android client: server settings saved without restarting the application ("Save" button) and checked as an
  IPv4 address; the "Server state" button takes the availability of the SAM into account; synchronous REST calls
  instead of RxJava and EventBus.
- Dashboard: built with Vite instead of Create React App, transactions streamed by the server (Server-Sent Events),
  entry page no longer cached, selected menu entry highlighted.
- Log messages written with the same template in all the components (`Message [key=value]`), at the levels described in
  the README; the rejections of the cards are logged once, where they are detected.
- Names of the classes, methods, variables, and resources harmonized with the ticketing vocabulary and the naming
  conventions described in the README.
- Common library included in the builds as a separate build (Gradle composite build) instead of a subproject.
- READMEs reviewed against the code and the build (each information in a single place, same structure, sentence case,
  English typography); the changelogs of the archived repositories are moved to `docs/history/`.

### Fixed
- Common library: a field value whose high bit is set was truncated when encoded (for example, a counter of 16,777,215
  written as 65,535 on a storage card).
- Validation app:
  - anti-passback: a card could be validated again a few seconds after a first validation, debiting a trip twice (the
    time of the event, recorded to the minute, was compared with the exact time);
  - Calypso cards: the priority `31` of the expired or exhausted contracts is written in the event when the card is
    rejected; contracts of unknown type are no longer accepted without debit; the type of the contract used is its
    `ContractTariff`, not its priority in the event;
  - a card that cannot be selected is rejected with the selection error, instead of running the validation procedure
    on the previous card;
  - crash at startup with the mocked storage card library, and stop of the application on an unexpected error of the
    validation procedure;
  - the location was displayed as "null" when an interrupted validation was recovered.
- Inspection app: a Calypso contract of an unexpected version rejects the card; the validation period ends at the end
  of its last minute (it could end 59 seconds too early); the failure sound is given once; the waiting indicator no
  longer stays displayed after a failure.
- Validation and inspection apps: the Bluebird reader can be selected again on Android 13 and later (storage permission
  only requested up to Android 12).
- Sales server:
  - loading: the priorities of the event are kept (the priority `31` of the expired contracts was lost), a new contract
    is written in an empty or expired record, a season pass is renewed for 30 days from its end date, a single contract
    card keeps a usable ticket of another type, and a card without space is rejected (`CARD_FULL`) instead of a success
    without writing;
  - a card whose last event has an unexpected version is rejected (`EVENT_WRONG_VERSION`) instead of being loaded;
  - each card gets a unique application number at personalization (it was 1 for all the cards);
  - the tariff of an expired contract is returned as recorded (its type was lost);
  - the server starts without PC/SC reader, without SAM, or with the mocked storage card library;
  - dashboard: transactions no longer lost, missed, or displayed twice, and recorded once with their actual result.
- Sales Android client: the statuses returned by the server were interpreted with a shift of one (wrong message, screen
  stuck on the loading animation); the type of a card which is not the one read before is displayed.
- Sales multiplatform client: an error returned by the server when reading the card is displayed as an error, instead of
  a card without contract.
- Sales .NET client: the number of trips is sent as a decimal number (10 trips were refused and 20 trips loaded 14).

### Removed
- Coppernic C-One 2 terminal support (plugin not updated since 2022).
- Stored value contract type (`PriorityCode.STORED_VALUE`): it could not be created by the demo, the contract tariff
  `3` being now handled as unknown.
- Sales Android client: "Wearable" and "Embedded Secure Element" card media, which had no reader.
- Multiplatform client: iOS Intel simulator target (`iosX64`), no longer supported by Compose Multiplatform.
- Unused dependencies: dagger-android, kapt, `kotlin-stdlib-jdk8`, `log4j` `1.2.17`, MultiDex, RxJava, EventBus, Koin,
  `material-icons-extended` (about 8 MB of the multiplatform APK), `slf4j-simple`, and the Create React App toolchain.
- Unused code and resources detected by Android Lint and code analysis.
